# Recipe Unlocks

Recipe Unlocks закрывает выбранные настройками рецепты отдельно для каждого игрока. На верстаке и других поддерживаемых рабочих местах закрытый рецепт не даёт результата, даже если правильно разложить ингредиенты. Администратор выбирает, как открывать рецепты: обычным способом Minecraft или за действия, записанные в конфиге.

Например, можно открыть печь после добычи 20 блоков камня, лук после двух попаданий по скелету и подбора трёх нитей, а факелы после трёх прыжков. Готовыми предметами пользоваться можно: мод ограничивает изготовление, а не владение вещами.

| Компонент | Версия |
|---|---|
| Minecraft | 26.2 |
| NeoForge, на котором собирается мод | 26.2.0.93 |
| Recipe Unlocks | 0.2.0 |
| Java для сборки | JDK 25 |

Мод ставится на сервер NeoForge. Игрокам Recipe Unlocks устанавливать не нужно: для подключения используется клиент NeoForge той же версии. В одиночной игре jar нужен в сборке, которая запускает мир, поскольку она же запускает встроенный сервер.

## Установка

Для выделенного сервера:

1. Подготовьте сервер Minecraft 26.2 с NeoForge. В репозитории используется NeoForge 26.2.0.93.
2. Остановите сервер. Если мир уже используется, сохраните его резервную копию.
3. Возьмите собранный `recipe_unlocks-0.2.0.jar` или соберите его по [инструкции ниже](#сборка-и-тестовые-запуски).
4. Поместите jar в папку `mods` сервера.
5. Запустите сервер. Мод создаст `config/recipe-unlocks.toml`, если файла ещё нет.
6. Настройте этот файл и выполните в игре `/unlocks reload` от имени оператора.

В одиночной игре положите jar в `mods` своей сборки NeoForge. Настройки находятся в `config/recipe-unlocks.toml` этой сборки. Для административных команд в мире должны быть разрешены команды.

Пути `mods/`, `config/` и `logs/` в этой инструкции отсчитываются от рабочей папки сервера или сборки. Если сервер запущен отдельно от клиента, редактировать нужно серверный конфиг.

В создаваемом файле оба основных переключателя включены, но все примеры правил закомментированы. Поэтому по умолчанию действуют ограничения по обычной книге рецептов, а собственных заданий ещё нет. Чтобы включить пример из файла, уберите `#` в начале его строки.

Установка в существующий мир не отбирает уже изученные рецепты. Это относится и к рецептам, для которых вы позже добавите правило.

## Первый пример: факелы за три прыжка

Этот пример закрывает только факелы. Остальные рецепты остаются доступны. Для проверки удобнее взять новый тестовый мир или нового игрока: старые открытия и сохранённые счётчики могут повлиять на результат.

Сохраните в `config/recipe-unlocks.toml`:

```toml
lock_all_recipes = false
template_unlocks = true

[unlocks]
torch = stat jump 3
```

Администратор выполняет в чате игры:

```mcfunction
/unlocks reload
/gamemode survival
/give @s coal 1
/give @s stick 1
/unlocks progress @s
```

Проверьте ответ `reload`: правило должно примениться без замечаний. В прогрессе факела будет показано условие и текущее число прыжков.

Теперь положите уголь над палкой в сетке инвентаря. Пока условие не выполнено, результата не будет. Закройте инвентарь и прыгните три раза на любом блоке. После третьего прыжка откроются рецепты факелов, появится уведомление книги рецептов, и тот же крафт даст результат.

Оператор может проверить открытие:

```mcfunction
/unlocks progress @s
```

У факела появится `открыт`. Самому игроку для выполнения условия команды не нужны. В примере они используются администратором для подготовки и проверки.

## Как пользоваться модом игроку

Выполняйте условия, которые задал администратор. Если у предмета есть правило, обычное получение ингредиентов не заменяет это условие. Например, наличие палки и угля не откроет факел, если для него требуется три прыжка.

Прогресс у каждого игрока свой. Действие одного игрока не выполняет условие за другого. После выхода из игры и перезапуска сервера накопленное сохраняется.

Когда правило выполнено, мод выдаёт соответствующие рецепты в книгу. Если правило записано для предмета, могут открыться сразу несколько способов его изготовления.

В выживании закрытый рецепт нельзя использовать. В творческом режиме блокировка не действует, но действия не увеличивают счётчики. Действия в режиме наблюдателя тоже не учитываются.

У обычных игроков нет команд Recipe Unlocks. В частности, `/unlocks progress @s` требует прав оператора. Отдельного меню заданий или команды просмотра прогресса без этих прав сейчас нет. Условия нужно сообщить игрокам отдельно.

## Настройки и режимы

Все настройки пишутся до раздела `[unlocks]`:

```toml
lock_all_recipes = true
template_unlocks = true
lock_recipes_without_unlock = false
lock_crafter = true
block_modded_stations = true

[unlocks]
torch = stat jump 3
```

### Два основных переключателя

`lock_all_recipes` закрывает ещё не изученные рецепты, которые Minecraft умеет выдавать игроку. `template_unlocks` включает ваши правила из `[unlocks]`. Они работают независимо.

| `lock_all_recipes` | `template_unlocks` | Как работает мод |
|---|---|---|
| `true` | `true` | Неизученные рецепты закрыты. Рецепт с правилом открывается за выполнение правила; остальные открываются обычным способом Minecraft. |
| `true` | `false` | Неизученные рецепты закрыты и открываются обычным способом Minecraft. Правила из файла не действуют. |
| `false` | `true` | Закрыты только рецепты с действующими правилами. Остальное можно изготовить без изучения. |
| `false` | `false` | Мод ничего не закрывает. |

Таблица описывает обычные рецепты. Специальные рецепты, например копирование карт, не блокируются. Судьба рецептов, которые игра вообще не умеет выдавать, зависит от `lock_recipes_without_unlock`.

Если включён `template_unlocks`, но действующих правил нет, этот переключатель сам по себе ничего не ограничивает.

### Все настройки

| Настройка | По умолчанию | Что меняет |
|---|---|---|
| `lock_all_recipes` | `true` | Требует изучить рецепт перед изготовлением, даже если для него не задано собственное правило. |
| `template_unlocks` | `true` | Включает правила из `[unlocks]`. Для рецептов с правилом обычная выдача задерживается до выполнения условия. |
| `lock_recipes_without_unlock` | `false` | При `lock_all_recipes = true` определяет, закрывать ли рецепты, для которых нет ни обычного открытия через достижения, ни действующего правила. При `false` они доступны. При `true` сами по себе они не откроются; оператор может выдать их командой. |
| `lock_crafter` | `true` | Автокрафтер проверяет доступ к ограничиваемому рецепту у игрока, который поставил блок. Этот игрок должен быть в сети. При `false` такая проверка отключена. |
| `block_modded_stations` | `true` | Скрывает закрытые рецепты от стандартного поиска рецептов, когда станком пользуется игрок. Не охватывает все собственные механизмы сторонних модов. |

Для сборки с другими модами сначала оставьте `lock_recipes_without_unlock = false`. Иначе можно закрыть рецепты станка, для которых ни Minecraft, ни ваш конфиг не предусматривают способа открытия.

Если станок другого мода начал работать неправильно, проверьте его с `block_modded_stations = false` и примените конфиг через `/unlocks reload`. Это отключает общий фильтр поиска для таких станков; обычные проверки верстака, печей и других встроенных рабочих мест остаются.

### Как применить изменения

1. Измените серверный `config/recipe-unlocks.toml` и сохраните его в UTF-8.
2. Выполните `/unlocks reload` в игре от имени оператора.
3. Прочитайте число применённых правил и замечания в ответе.
4. Проверьте нужного игрока через `/unlocks progress <игрок>`.

Перезапуск сервера не требуется. Команда перечитывает файл, но не редактирует его: для добавления и изменения правил нужен текстовый редактор.

## Как записывать правила

Одна строка задаёт, что открыть и какое условие выполнить:

```text
что_открыть = действие цель количество
```

Например:

```toml
[unlocks]
furnace = break stone 20
```

После 20 засчитанных разрушений камня игрок получит рецепты печи. Само действие `break` не требует, чтобы блок выпал предметом. Если нужна именно статистика добычи, используйте `mine`; различие описано в [таблице действий](#действия-и-статистика).

### Левая часть: предмет, тег или отдельный рецепт

| Запись | Что открывается |
|---|---|
| `torch` или `minecraft:torch` | Все найденные обычные рецепты, результатом которых служит факел. |
| `create:cogwheel` | Рецепты шестерёнки из установленного мода с этим ID. Сам пример не устанавливает Create. |
| `"#minecraft:planks"` | Рецепты всех предметов из тега досок. Слева нужен тег предметов. |
| `minecraft:iron_ingot_from_blasting_raw_iron` | Один конкретный рецепт получения железного слитка из сырого железа в плавильной печи. |

Префикс `minecraft:` можно опустить. Для предметов других модов укажите их пространство имён, например `create:`. Звёздочка `*` слева не поддерживается.

Если одно и то же имя подходит предмету и рецепту, мод сначала ищет рецепты, которые дают этот предмет. Только если таких рецептов нет, ищется отдельный рецепт с указанным ID. Поэтому `torch` не обязательно означает один рецепт: это предмет, у которого есть несколько способов изготовления.

Для некоторых сторонних рецептов поиск по выходному предмету недоступен. В таком случае задайте ID самого рецепта.

### Где взять ID

ID предмета можно увидеть через `F3+H`: включите расширенные подсказки и наведите курсор на предмет. На некоторых клавиатурах для `F3` нужна клавиша `Fn`.

ID рецепта и ID предмета могут различаться. У одного предмета могут быть отдельные рецепты крафта, переплавки и обжига. Для команд `/recipe give` и `/recipe take` нужен именно ID рецепта. Начните вводить его в чате и используйте подсказки `Tab`. Источником также служат данные рецептов соответствующего мода или датапака.

Тег объединяет несколько объектов. Например, `#minecraft:logs` позволяет считать подходящие брёвна вместе. Тег должен существовать в реестре, который использует действие: для блока нужен тег блоков, для еды тег предметов, для существ тег типов существ.

### Цель и количество

Справа после действия обязательно указывается цель:

| Цель | Пример | Значение |
|---|---|---|
| Конкретный ID | `break stone 5` | Сломать пять блоков камня. |
| Тег | `break #minecraft:logs 5` | Сломать суммарно пять подходящих брёвен. |
| `*` | `break * 5` | Сломать пять любых блоков. |

Если количество не указано, требуется одно действие или одна единица статистики. Например, `eat apple` равнозначно `eat apple 1`.

Количество должно быть целым числом от `1` до `2147483647`. Ноль, отрицательные числа и дроби не принимаются. Для событийных действий это число событий, для статистики единицы определяет сама игра.

Запись `jump 5` неверна: число окажется на месте цели. Для пяти прыжков с любого блока используйте `jump * 5` или `stat jump 5`.

### Кавычки, комментарии и строки

Файл с расширением `.toml` читает собственный построчный парсер мода. Он поддерживает показанные здесь настройки и правила, но не весь синтаксис TOML. Не используйте массивы или многострочные выражения.

Эти записи равнозначны:

```toml
[unlocks]
torch = break stone 3
```

```toml
[unlocks]
"torch" = "break stone 3"
```

Внешние кавычки могут быть одинарными или двойными. Внутри выражения отдельные слова в кавычки не заключаются. Экранирование кавычек не поддерживается.

Строка, которая начинается с `#`, считается комментарием. Поэтому тег слева обязательно заключайте в кавычки:

```toml
[unlocks]
"#minecraft:planks" = break #minecraft:logs 1
```

Справа `#minecraft:logs` остаётся тегом. Для комментария после выражения отделяйте `#` пробелами:

```toml
[unlocks]
furnace = break stone 20 # двадцать разрушений камня
```

Настройки размещайте до `[unlocks]`, а каждое правило на отдельной строке. Неизвестные разделы пропускаются. Если повторить настройку, действует последнее корректное значение и появляется замечание. Если повторить тот же ключ правила, последующая строка пропускается: исправляйте исходную строку.

## Действия и статистика

### События игрока

| Действие | Пример условия | Что считается |
|---|---|---|
| `break` | `break stone 20` | Успешное разрушение блока игроком. Отменённое событие не считается. |
| `place` | `place #minecraft:planks 10` | Установка подходящего блока. |
| `jump` | `jump cobblestone 3` | Прыжок с указанного опорного блока. Здесь нужно стоять на булыжнике. |
| `hit` | `hit skeleton 2` | Попадание по существу с фактически нанесённым уроном. |
| `kill` | `kill zombie 2` | Убийство подходящего существа игроком. |
| `eat` | `eat apple` | Завершённое использование предмета, обычно съеденная еда или выпитое зелье. |

`hit` и `kill` не учитывают других игроков. Удар во время неуязвимости существа, который не нанёс урона, не увеличит `hit`.

Для `break`, `place` и `jump` можно указывать блок, тег или предмет блока. Например, `break torch` учитывает и настенный факел.

### Статистика Minecraft

Эти названия служат короткими именами типов статистики. Мод считает новые прибавки, которые начисляет сама игра:

| Действие | Тип статистики | Пример условия | Что учитывать |
|---|---|---|---|
| `pickup` | `picked_up` | `pickup string 3` | Подбор предметов с земли. `/give` кладёт вещи в инвентарь и не заменяет подбор. |
| `drop` | `dropped` | `drop dirt 5` | Число выброшенных предметов, а не обязательно число нажатий `Q`. |
| `use` | `used` | `use snowball 3` | Использование, за которое игра начислила статистику предмета. Не любое нажатие правой кнопки. |
| `craft` | `crafted` | `craft stick 4` | Число полученных предметов по статистике изготовления. Крафт, получение результата плавки или торговля учитываются там, где игра начисляет эту статистику. |
| `mine` | `mined` | `mine iron_ore 2` | Статистика добычи указанного блока. Отличается от событийного `break`. |
| `stat` | `custom` | `stat jump 100` | Именованный счётчик общей статистики. Здесь `jump` означает любые прыжки. |

Если один крафт дал четыре палки и игра начислила четыре единицы статистики, условие `craft stick 4` выполнится за этот крафт. Аналогично подбор стопки из трёх нитей может сразу дать три единицы `pickup`.

Другие примеры общей статистики: `stat sleep_in_bed`, `stat fish_caught 5`. Вместо короткого имени можно написать существующий тип статистики из игры или установленного мода. Например, `killed_by zombie` требует, чтобы игрок погиб от зомби, а `minecraft:broken wooden_pickaxe` учитывает сломанную деревянную кирку.

Название типа и цель должны существовать в реестрах игры. Произвольное слово не создаёт новое действие. Счётчики расстояния, времени и других величин используют единицы своей статистики; число в правиле не переводится автоматически в метры или секунды.

## Несколько условий в одном правиле

`&` требует выполнения обоих условий. `|` позволяет выполнить любое из них. Порядок действий не задаётся: яблоко можно съесть до добычи камня, если мод уже отслеживает эти условия.

```toml
[unlocks]
torch = break stone 3 & (eat apple | drop stick)
```

Здесь нужно сломать три блока камня и дополнительно либо съесть яблоко, либо выбросить палку. Одного яблока без камня недостаточно.

| Связка | Допустимые записи |
|---|---|
| И | `&`, `&&`, `+`, `,`, `and`, `и` |
| ИЛИ | `\|`, `\|\|`, `or`, `или` |

Словесные связки не зависят от регистра. В длинных правилах удобнее придерживаться `&`, `|` и скобок.

И выполняется раньше ИЛИ. Выражение `break stone 3 & eat apple | kill zombie` означает `(break stone 3 & eat apple) | kill zombie`: достаточно либо камня вместе с яблоком, либо одного зомби. Чтобы камень требовался в обоих случаях, напишите `break stone 3 & (eat apple | kill zombie)`.

Условий отрицания, обязательной последовательности шагов и ограничений по времени в этом синтаксисе нет.

### Пересекающиеся правила

Если один рецепт попал под несколько разных правил, достаточно выполнить любое из них. Условия разных строк не складываются через И.

Например, эта запись разрешает открыть факел одним из двух способов:

```toml
[unlocks]
torch = break stone 3
minecraft:torch = eat apple
```

То же относится к пересечению тега предметов и отдельного предмета. Если нужны оба требования, объедините их в одной строке:

```toml
[unlocks]
torch = break stone 3 & eat apple
```

## Примеры правил

Это отдельный пример конфига, а не продолжение предыдущих блоков. Используйте один раздел `[unlocks]` и одну строку для каждого выбранного ключа.

```toml
lock_all_recipes = false
template_unlocks = true
lock_recipes_without_unlock = false
lock_crafter = true
block_modded_stations = true

[unlocks]
# Любые доски: сломать одно бревно из тега.
"#minecraft:planks" = break #minecraft:logs 1

# Верстак: сломать три бревна. Первое бревно уже идёт в этот счёт.
crafting_table = break #minecraft:logs 3

# Палки: поставить две доски.
stick = place #minecraft:planks 2

# Железная кирка: изготовить четыре палки.
iron_pickaxe = craft stick 4

# Факелы: трижды прыгнуть с булыжника.
torch = jump cobblestone 3

# Меч и лук: нанести урон свинье и убить зомби.
wooden_sword = hit pig 2
bow = kill zombie

# Хлеб: съесть яблоко. Лестницы: подобрать три нити с земли.
bread = eat apple
ladder = pickup string 3

# Сундук: выбросить пять единиц земли.
chest = drop dirt 5

# Печь: использовать три снежка. Щит: десять любых прыжков.
furnace = use snowball 3
shield = stat jump 10

# Все рецепты слитка: добыть железную руду и выполнить одну из двух веток.
iron_ingot = mine iron_ore & (eat bread | kill zombie 2)
```

Пример для установленного мода с предметом `create:cogwheel`:

```toml
[unlocks]
create:cogwheel = place #minecraft:logs 10 | stat sleep_in_bed
```

Если Create или нужного предмета нет в сборке, такое правило не сможет включиться.

При составлении своих заданий проверьте, доступны ли средства для их выполнения. Например, `torch = craft torch` не даст получить первый факел через закрытый крафт. Понадобится другой источник предмета, выдача оператором или другое условие.

## Команды

### Что доступно игроку и администратору

Все три команды мода требуют прав оператора `gamemaster`. Обычному игроку они недоступны, включая просмотр собственного прогресса. Администратор может использовать их для себя и для другого игрока в сети.

| Команда в чате игры | Обычный игрок | Оператор | Что делает |
|---|---|---|---|
| `/unlocks reload` | Нет | Да | Перечитывает конфиг, применяет корректные настройки и правила, выводит замечания. |
| `/unlocks progress <игрок>` | Нет | Да | Показывает состояние рецептов и прогресс по действующим правилам выбранного игрока. |
| `/unlocks reset <игрок>` | Нет | Да | Сбрасывает все счётчики игрока и отзывает рецепты, которые ему выдавали правила мода. |

Это полный набор команд `/unlocks`; сокращений и других подкоманд сейчас нет. Один `/unlocks` без подкоманды ничего не выполняет. У `progress` и `reset` аргумент игрока обязателен.

Вместо `<игрок>` укажите ник или селектор, который выбирает ровно одного игрока в сети. Угловые скобки вводить не нужно. `@s` означает отправителя команды и подходит для вызова игроком из чата:

```mcfunction
/unlocks progress @s
/unlocks progress Alex
```

В консоли сервера начальный `/` обычно опускают. У консоли нет собственного персонажа, поэтому вместо `@s` укажите ник. Аргумент `<игрок>` этих команд не предназначен для редактирования данных офлайн-игрока.

### Просмотр прогресса

`progress` выводит строку для каждого действующего правила. Если изучены все рецепты, которые охватывает правило, показывается `открыт`. В остальных случаях выводится выражение с текущими числами.

Рецепт, выданный через `/recipe give`, тоже виден как изученный: статус `открыт` определяется наличием рецептов в книге игрока.

За один ответ выводится не более 40 строк правил. Если их больше, мод сообщает число оставшихся; переключения страниц сейчас нет. Когда правил нет или они отключены, команда объясняет это в ответе.

### Полный сброс прогресса игрока

Для сброса своего прогресса оператор выполняет:

```mcfunction
/unlocks reset @s
```

Команда обнуляет все счётчики правил у выбранного игрока и отбирает рецепты, выданные этими правилами. Изготовленные предметы остаются в инвентаре. Если есть рецепты для отзыва, открытый контейнер закрывается, чтобы старый результат крафта нельзя было забрать после сброса.

Рецепты, полученные только обычным способом или только через `/recipe give`, этим сбросом не отзываются. Если рецепт когда-то выдавался правилом, последующая ручная выдача не убирает его из списка для сброса.

У команды нет варианта «сбросить только одно правило» или «обнулить счётчик одного предмета».

### Стандартная выдача рецепта: `/recipe give`

Это команда Minecraft. Мод специально разрешает оператору выдать рецепт даже при невыполненном условии:

```mcfunction
/recipe give <игрок> <id_рецепта>
/recipe give <игрок> *
```

Например:

```mcfunction
/recipe give @s minecraft:torch
```

Команда открывает указанный рецепт, но не заполняет счётчики правил. Вариант `*` выдаёт все рецепты, поэтому для проверки одного условия удобнее указывать конкретный ID.

Если у предмета несколько рецептов, выдача одного ID открывает только этот способ. Например, крафт факела из угля и из древесного угля может иметь разные ID. Подсказки `Tab` помогают выбрать нужный.

### Как убрать конкретный изученный рецепт: `/recipe take`

Оператор может отобрать один рецепт стандартной командой Minecraft:

```mcfunction
/recipe take <игрок> <id_рецепта>
```

Например, отобрать у себя конкретный рецепт факела:

```mcfunction
/recipe take @s minecraft:torch
```

Для отзыва всех рецептов у себя используется:

```mcfunction
/recipe take @s *
```

Здесь тоже нужен ID рецепта. Если у предмета есть другой изученный способ изготовления, предмет всё ещё можно будет получить этим способом.

`take` удаляет рецепт из книги, но не обнуляет счётчики Recipe Unlocks. Если условие мода уже выполнено, рецепт откроется снова после перезахода игрока или успешного `/unlocks reload`. После изменения рецептов или достижений мод также может проверить прогресс и выдать рецепт заново. Это не постоянный запрет.

Рецепт без правила может повторно открыться обычным способом Minecraft. Если текущие настройки вообще не ограничивают этот рецепт, его удаление из книги само по себе не запретит крафт.

Для повторной проверки условия с нуля нужен `/unlocks reset <игрок>`, но он сбрасывает весь прогресс правил этого игрока. Для изолированной проверки одного задания удобнее новый тестовый игрок или мир.

## Как сохраняется прогресс и что происходит при правке правил

### Какие действия засчитываются

Мод хранит собственные счётчики по UUID игрока. Старые значения из меню статистики Minecraft в них не переносятся. Если игрок прыгнул 500 раз до появления отслеживаемого условия `stat jump`, эти прыжки не выполнят новое задание.

Засчитываются действия в выживании и других режимах, кроме творческого и наблюдателя. Действия технических `FakePlayer`, которыми пользуются некоторые моды, не учитываются.

### Общий счётчик у нескольких правил

Счётчик привязан к сочетанию действия и цели, а не к выходному предмету или требуемому количеству:

```toml
[unlocks]
torch = break stone 3
furnace = break stone 10
```

Один сломанный камень продвигает оба задания. На третьем открываются факелы, на десятом печь. Для печи не требуется добывать ещё десять камней после факелов.

Короткие и полные равнозначные имена нормализуются: `stone` и `minecraft:stone`, `pickup` и `picked_up` обозначают ту же цель или тип счётчика. При этом `break stone`, `mine stone` и `break #minecraft:base_stone_overworld` остаются разными сочетаниями.

Мод не хранит бесконечную историю действий. Значение растёт до наибольшего порога, нужного действующим правилам. Если единственному правилу требовалось три камня, после третьего лишние разрушения для этого счётчика не накапливались. Увеличение требования до 20 не восстановит их из статистики Minecraft.

### Изменение и удаление правил

После `/unlocks reload` учитывается уже сохранённый прогресс:

- Уменьшение порога может сразу открыть рецепт.
- Новое правило с уже отслеживаемыми действием и целью использует прежний счётчик. Оно не обязано начинаться с нуля.
- Для другой пары действия и цели счёт начинается с нуля, если её раньше не отслеживали.
- Удаление правила не стирает старый счётчик. Если вернуть такое условие, прежнее значение может использоваться снова.
- Добавление или усложнение правила не отнимает рецепт, который игрок уже изучил.

Когда правило удалено или отключено, мод выдаёт обычные открытия, которые Minecraft уже пытался дать игроку, но которые были задержаны этим правилом. Это не выдача всех рецептов подряд: рецепт, для которого обычное открытие ещё не происходило, автоматически не появится.

### Где лежат данные

Собственный прогресс мода сохраняется вместе с миром:

```text
<папка_мира>/data/recipe_unlocks/progress.dat
```

Там хранятся счётчики, сведения о рецептах, выданных правилами, и о задержанных обычных выдачах. Изученные рецепты также сохраняются в обычных данных игрока Minecraft. Поэтому удаление одного `progress.dat` не равно корректному сбросу всех открытий.

Для резервной копии сохраняйте мир целиком и отдельно `config/recipe-unlocks.toml`.

## Где действует блокировка

| Место | Что происходит с закрытым рецептом |
|---|---|
| Сетка в инвентаре и верстак | Результат закрытого рецепта не выдаётся. Если подходят несколько рецептов, может использоваться доступный. |
| Кузнечный стол | Закрытый рецепт не даёт результата. |
| Камнерез | Выбор закрытого рецепта отклоняется. |
| Печь, плавильная печь и коптильня | Игрок не может положить сырьё, если для него закрыты все подходящие рецепты, и не может забрать результат закрытого рецепта. Проверки действуют также при shift-click и размещении через книгу рецептов. |
| Костёр | Игрок не может положить еду, если все подходящие рецепты закрыты. |
| Автокрафтер | При `lock_crafter = true` проверяется доступ владельца к ограничиваемому рецепту. |
| Станки других модов | При `block_modded_stations = true` закрытые рецепты скрываются из стандартного поиска во время действия игрока. |

### Автокрафтер и его владелец

Владельцем считается игрок, который поставил автокрафтер. Для ограничиваемого рецепта при `lock_crafter = true` должны выполняться два условия: владелец в сети и рецепт ему доступен.

У старого автокрафтера, поставленного до установки мода, может не быть записанного владельца. Для такого рецепта он не сработает. Переустановка блока игроком назначает владельца.

Рецепты, которые мод вообще не ограничивает, не требуют онлайн-владельца. `lock_crafter = false` отключает эту проверку автокрафтера целиком.

### Что остаётся доступно

Мод не запрещает пользоваться готовой вещью. Её можно получить от другого игрока, из сундука или командой, даже если собственный рецепт ещё закрыт.

У печей нет владельца, и сам процесс плавки не останавливается. Загрузка и выгрузка автоматикой без участия игрока, например воронками, не ограничиваются личной книгой рецептов. Содержимое сломанной печи выпадает обычным способом.

Специальные рецепты Minecraft, например копирование карт, покраска кожаной брони и специальные рецепты фейерверков, не блокируются. Творческий режим обходит ограничения крафта. Это не означает, что он автоматически изучает все рецепты с условиями.

Поддержка сторонних станков зависит от того, как они ищут рецепт. Если машина использует свою систему рецептов или работает в фоне без действия игрока, общий фильтр может её не охватить. Установка мода не гарантирует ограничения всей автоматики сборки.

## Ошибки и частые вопросы

### Правило не появилось после редактирования

Проверьте, что изменён серверный файл, строка находится под `[unlocks]`, не начинается с `#`, а `template_unlocks = true`. Выполните `/unlocks reload` и прочитайте замечания.

Синтаксические ошибки показываются с номером строки; ошибка выражения может содержать позицию символа. При неизвестном ID или теге в сообщении обычно указан ключ правила, но номер строки может отсутствовать.

Ошибка одной строки не отменяет корректные соседние правила. Если неверна цель справа, правило может остаться действующим, но эта ветка не выполнится. Если слева не найден ни предмет с рецептами, ни тег, ни отдельный рецепт, правило не попадёт в действующий набор.

Если файл нельзя прочитать целиком, например из-за повреждённой UTF-8, `reload` сохраняет прежнюю конфигурацию и сообщает об этом. При такой ошибке на запуске прежней конфигурации в памяти ещё нет: используется запасной режим с `lock_all_recipes = true` и без правил. Исправьте файл и повторите `reload`.

### После добавления условия рецепт всё равно крафтится

Проверьте режим игрока и факт изучения рецепта. Творческий режим обходит блокировку. Уже изученный рецепт не отзывается автоматически при добавлении правила.

Ещё одна причина: у предмета несколько рецептов, а правило или `/recipe take` затронули только один. Для ограничения всех найденных способов используйте слева ID предмета.

### Старые прыжки не выполнили новое правило

Мод считает новые прибавки с момента, когда начал отслеживать эту пару действия и цели. Историческая статистика не переносится. Если такую пару уже отслеживало другое правило, используется сохранённый счётчик мода.

### `/give` не увеличивает `pickup`

`pickup` требует подбора с земли. Для ручной проверки выбросьте предмет и подберите его. Выдача прямо в инвентарь не создаёт нужную статистику подбора.

### Удары или прыжки не засчитываются

Для `hit` нужен фактически нанесённый урон. Частые удары во время неуязвимости и удары по игрокам не подходят.

Для `jump cobblestone` булыжник должен быть опорным блоком в момент прыжка. Если нужен любой прыжок, используйте `stat jump` или `jump *`. В творческом режиме и режиме наблюдателя счётчики не растут.

### После `/recipe take` рецепт вернулся

Команда не сбрасывает выполненное условие. При входе игрока или перезагрузке конфига мод проверяет сохранённый прогресс и выдаёт недостающий рецепт снова. Для сброса всех условий игрока существует `/unlocks reset`; точечного сброса одного правила сейчас нет.

### Предмет с правилом открылся раньше ожидаемого

Проверьте пересекающиеся правила и общие счётчики. Рецепт из тега может одновременно попадать под отдельное правило предмета; для открытия достаточно любого из них. Новое правило также может использовать счётчик, накопленный для другого задания.

### Автокрафтер остановился, а печь с воронкой работает

Это разные проверки. У автокрафтера сохраняется владелец, а у печи нет. При `lock_crafter = true` владельцу автокрафтера нужно быть в сети и иметь доступ к рецепту. Автоматическая плавка без участия игрока не проверяет его личный прогресс.

### Где смотреть сообщения

Ответы административных команд приходят в чат. Журнал сервера находится в `logs/latest.log`; сообщения мода содержат `[Recipe Unlocks]`. Если правил или замечаний больше 40, чат показывает первые 40 строк и число оставшихся. Подробности загрузки проверяйте в журнале.

## Обновление, резервная копия и удаление мода

Перед обновлением остановите сервер и сохраните мир вместе с серверным конфигом. Замените jar мода в `mods`, затем запустите сервер и проверьте загрузку в `logs/latest.log`. Текущая сборка рассчитана на Minecraft 26.2; минимальная версия NeoForge в метаданных 26.2.0.93. Перед сменой версии окружения проверьте совместимость мода.

Чтобы временно отключить ограничения, установите оба переключателя в `false` и выполните `/unlocks reload`:

```toml
lock_all_recipes = false
template_unlocks = false
```

Меняйте существующие строки до `[unlocks]`, а не добавляйте их в конец раздела правил. Это не удаляет сохранённые счётчики. При отключении правил мод также освобождает ранее задержанные обычные выдачи.

Для удаления мода остановите сервер, уберите его jar из `mods` и запустите сервер снова. Ограничения Recipe Unlocks перестанут действовать. Удаление мода не сбрасывает книгу рецептов и не возвращает мир к состоянию до установки.

## Сборка и тестовые запуски

Для сборки нужен JDK 25. Gradle Wrapper уже находится в репозитории. Следующие команды выполняются в терминале из корня репозитория, не в чате Minecraft.

Собрать jar:

```sh
./gradlew build
```

Результат для текущей версии: `build/libs/recipe_unlocks-0.2.0.jar`.

Запустить игровые тесты на сервере без окна:

```sh
./gradlew runGameTestServer
```

Тестовое окружение находится в `run/gametest`. Исходники тестов лежат в `src/gametest` и не входят в выпускаемый jar.

Запустить сервер разработки с модом:

```sh
./gradlew runServer
```

Запустить клиент NeoForge без Recipe Unlocks:

```sh
./gradlew runCleanClient
```

Подключить такой клиент сразу к тестовому серверу:

```sh
./gradlew runCleanClient -PjoinServer=127.0.0.1:25565
```

Клиентское тестовое окружение находится в `run/clean-client`. В `-PjoinServer=` можно указать другой адрес и порт уже запущенного сервера.
